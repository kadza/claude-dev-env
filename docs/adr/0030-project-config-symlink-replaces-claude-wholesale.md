# Project config symlink replaces `.claude/` wholesale, not merged

When `--project-config <path>` is given, the project's `.claude/` directory (and `CLAUDE.md`) is replaced entirely by symlinks into `<path>/.claude` and `<path>/CLAUDE.md`, including whatever the template put at `.claude/settings.local.json`. This matches the existing working pattern from `be-dev-claude-code-config` (whole-directory symlink, edits write back automatically) and keeps the mental model simple: once a project has a project config attached, that project config is the sole owner of `.claude/` for that project, with no merge logic to reconcile template-provided permissions against externally-provided skills/permissions. Rejected: a partial symlink of individual subpaths (e.g. only `.claude/skills`) while keeping the template's `settings.local.json` in place — preserves tech-baseline permissions, but adds merge complexity and diverges from the working be-dev pattern for no clear benefit.
