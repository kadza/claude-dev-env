# Project config path is not persisted anywhere

`--project-config <path>` is a plain CLI flag with no backing marker file; a bare `d up` reconnect never re-supplies or remembers it. This is safe because devcontainer mounts are baked in only at container creation or `--rebuild` — a plain reconnect reuses the already-created container's mounts as-is, so the path is genuinely only needed at those two moments, and persisting it (e.g. under `claude-state/<name>/`) would add bookkeeping for information that's only ever read twice: once at creation, once per rebuild. Rejected: a marker file under `claude-state/<name>/`, read by `seed.sh`/`clone.sh`/`up.sh` on every invocation — would let a bare `d up` implicitly "remember" the path, but was passed over in favor of re-supplying it explicitly at the two moments it actually matters, rather than hidden persisted state.
