# Project config flag lives on `seed`/`clone`/`up`, not a new `d config` command

`--project-config <path>` is an optional flag added to the three existing commands that can create or recreate a container (`seed.sh`, `clone.sh`, `up.sh --rebuild`), parsed the same way `up.sh` already parses `--rebuild`, rather than a dedicated `d config <name> <path>` command. The flag's only job — export `PROJECT_CONFIG_DIR` before `devcontainer up`, and (re)point the project's `.claude`/`CLAUDE.md` symlinks — only ever needs to happen at the same moments those three commands already run, so a separate command would just be another entry point wrapping the same one-time setup, not a distinct lifecycle. Rejected: a standalone `d config <name> <path>` command mirroring `seed`/`clone`/`up`'s shape — keeps the flag's plumbing in one place, but adds a fourth top-level verb for something that's really an option on the existing ones, and still wouldn't remove the need to separately trigger `--rebuild` for the mount to take effect.
